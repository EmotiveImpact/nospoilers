`alerts` and `alert_events` require `installation_id`. Their standard readers join installation-derived workspace membership. Independent website attempts have immutable `workspace_id` and `source_origin_id`, but `upload-worker.ts` currently saves their report/proof without an alert. The independent shell consequently omits Alerts. Do not fabricate an installation, reuse another source's installation, or call uploaded findings ongoing alerts without a persisted response record.

## Required implementation

1. Add workspace ownership to the existing alert model and backfill mapped legacy records. Preserve historical unmapped records rather than assigning them to an arbitrary workspace. Permit installation-null alerts only with an explicit independent source/workspace. Guard ownership against mutation.
2. Make event ownership match the parent alert; keep history append-only. Preserve existing legacy event readers and public proof privacy boundaries.
3. Link website alerts to immutable saved attempt IDs, validating workspace/source equality. Do not infer links from names, URLs in prose, timestamps or current source state.
4. In website-result publication, persist evidence and the relevant alert atomically. Define retry deduplication and repeated-finding behaviour explicitly. A later passing scan must not rewrite a previous report; technical recheck and human disposition remain distinct.
5. Add workspace-authoritative list/detail/events/assignment/response access for independent alerts, with live membership, revocation and archive checks. Reuse stable member IDs and transactional response protection. Never convert a null installation into numeric zero.
6. Wire the approved Alerts layout in independent and mixed workspaces, retaining URL selection, independent status/owner filters, explicit response actions and scope-preserving related-result links. Empty/error/permission states must not substitute another tenant's alerts.
7. Include actual open exposure in Overview and shell counts, separately from delayed Coverage and immutable failed attempts.
8. Integrate notification configuration/delivery through the actual workspace owner/payer; no implicit sends, fake connected providers or inherited destinations from another workspace.

## Acceptance

- Independent website finding produces a readable response record linked to the exact saved attempt, without any GitHub installation.
- Retries do not duplicate initial alert/event/result associations.
- Viewer, revoked and foreign-workspace reads/writes behave according to the access contract; archive retains readable evidence but blocks response mutations.
- Resolve/reopen/assignment events do not edit reports or fabricate remediation. Recheck creates a new attempt under current ownership, plan and allowance.
- Legacy alert/history/notification/proof regressions pass after migration.
- Browser acceptance covers empty, active, failed, resolved, revoked-access and mixed-source workspaces, plus keyboard and narrow-screen behaviour.

Do not close B5 or Gate B from schema changes or a narrow worker test alone.
