## Verified current constraints

- `scan_api_tokens` requires an installation. Listing uses workspace-derived source membership, but revocation still joins `installation_users`. An explicitly granted workspace administrator can therefore pass route authorization yet fail revocation. Align this authority and test it before expanding credential ownership.
- Token minting is installation-scoped and checks capacity separately from insertion. Workspace minting needs transactional quota enforcement, live administrator/archive checks, and an audit event in the same transaction.
- `/api/v1/scan` authenticates to an installation and uses installation admission. Merely adding a workspace token settings screen would create unusable credentials for independent workspaces. Extend credential authentication and scan admission together; preserve existing CI clients.
- Notification destinations, delivery history and routing remain installation-owned. Independent website alerts exist, but cannot inherit another workspace's delivery destinations.
