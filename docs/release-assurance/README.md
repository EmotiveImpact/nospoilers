Status: active implementation on draft PR #44. Integration review remains open. Not a launch declaration.

## Start here

For product/commercial continuity, read [BUSINESS-NORTH-STAR.md](BUSINESS-NORTH-STAR.md) first. It preserves the company ambition, category strategy, pricing/revenue maths, retention thesis, release-intelligence model, agent strategy, behavioural design, acquisition/lead-generator logic, buyer segments, metrics and next-build order from the originating work.

[CONTEXT-AUDIT.md](CONTEXT-AUDIT.md) maps the substantive conversation to its durable home, distinguishes owner direction from proposals, and records corrections so earlier illustrations never become unsupported product claims. This is a structured context audit, not a verbatim chat archive or new app verification.

Read [RESEARCH-SNAPSHOT.md](RESEARCH-SNAPSHOT.md) for the dated competitor, pricing, market, B2B-outreach/legal, partner and ecosystem research. [COMMERCIAL-VALIDATION-PLAN.md](COMMERCIAL-VALIDATION-PLAN.md) adds the operational hypotheses: USD/GBP and annual-plan maths, customer-validation stages, metric definitions, channel/cost assumptions, risk register and decision gates. These proposals do not change pricing or authorise spending/outreach.

For implementation state, [INTELLIGENCE-HANDOFF.md](INTELLIGENCE-HANDOFF.md) describes the release-stream/history/baseline continuation and [ACCEPTANCE.md](ACCEPTANCE.md) maps the complete discussed vision to implemented, unverified and unbuilt work. The older [HANDOFF.md](HANDOFF.md) remains useful for the original companion but is superseded where the newer intelligence handoff conflicts.

[ARCHITECTURE.md](ARCHITECTURE.md) explains evidence/API boundaries. [BEHAVIOURAL-DESIGN.md](BEHAVIOURAL-DESIGN.md) records the customer-value, behavioural-economics and anti-dark-pattern decisions. [BEHAVIOURAL-EXPERIMENTS.md](BEHAVIOURAL-EXPERIMENTS.md) adds primary-source context, limits of transfer, seven testable hypotheses, task scripts and safety stop rules. Those experiments are not claimed as implemented or measured.

[BUILD-LOG.md](BUILD-LOG.md) records verification checkpoints. Revised outreach is in [OUTREACH-LIBRARY-v2.md](../growth/OUTREACH-LIBRARY-v2.md). Financial, research and implementation evidence have different meanings; keep them separate.

The product direction is release assurance: understand what a release's evidence says, what changed, whether it satisfies the adopted policy within recorded scope, what reached production where supported, what needs attention and what remains unknown. It is not 'NoSpoilers guarantees software is safe'.

The next engineering task remains integrated verification and one consistent release authority, not another documentation rewrite. This documentation consolidation changes no application code, runtime setting, billing contract or operational gate.
